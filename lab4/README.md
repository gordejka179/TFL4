# Исследование на КС
Смотрим пока только на правила `T->bb` и `T -> TaT` . Замечаем интересную вещь. Для строки 
`bbabbabba...abb` существует дерево разбора почти-бамбук (длинная палка). Например, так:
`T` -> `bbaT` -> `bbabbaT` -> `bbabbabbaT` и так далее (каждый раз раскрываем последнюю `T`). В таком случае `T.a` будет равно числу букв "a" в слове, которое получилось при раскрытии `T` (или глубине раскрытия `T`).  
А есть дерево разбора, когда будем последовательно заполнять каждый уровень в дереве (как в двоичной куче). Тогда `T.a` будет равно глубине раскрытия `T` , или `⌊log2(T#a)⌋ + 1`(Округление вниз).  
Возвращаемся к исходной системе. Смотрим на первое правило и его ограничение: `S -> TST` ; `T1.a < T2.a`. С учётом вышенаписанного ограничение будет эквивалентно 
`⌊log2(T1#a)⌋ + 1 < T2#a` . Из-за логарифма язык не будет являться КС-языком. Почти очевидно, что из-за логарифма язык не будет КС-языком (ну как с помощью автомата вычислять логарифм?). И всё же, строгое доказательство. Пересечём наш язык с языком L2 = (bba)* bbaaabb(abb)*. Покажем, что L2 - не КС. Для любого n > 0, есть слово w =  (bba)^(2^n - 1) bbaaabb(abb)^(n + 1), длина которого больше, чем n. Если при разбиении w = xuyvz слово u не содержит какой-то из блоков (bba) полностью, то при накачке вылетаем из языка, то же самое, если слово v не содержит какой-то из блоков (abb) полностью. Пусть слово u содержит x блоков (bba), слово v содержит y блоков (abb). Не забудем самое важное: длина слова uyv не больше, чем n. Тогда 3x + 5 + 3y <=n. Тогда y - n/3 + 5/3 <= -x. Применим накачку со степенью равной 0. Тогда заметим, что 2^n -1 -x >= 2^n - 1 + y - n/3 + 5/3 > 2^n - n/3. Заметим, что 2^(n - 1) >= 2^(n - y - 1). Поэтому если покажем, что 2^n - n/3 > 2^(n - 1), то слово вылетает из языка. Покажем это:
2^n - n/3 > 2^(n - 1)
2 - n / (3 * 2^(n - 1)) > 1
n / (3 * 2^(n - 1)) < 1. 
А это уже очевидно.  
Итак, язык не является контекстно-свободным.

# Написание наивного и умного парсеров
От логарифма перейдём к степеням двойки `⌊log2(T1#a)⌋ < T2#a - 1` , тогда `log2(T1#a) < T2#a - 1`, тогда `T1#a < 2 ^ (T2#a - 1)`.
Дальше избавляемся от левой рекурсии и получаем грамматику:

`S -> TSTP` ; `T1#a < 2 ^ (T2#a - 1)`  
`S -> TST`   
`S -> aaaP`  
`S -> aaa`  
`P -> bSP`  
`P -> bS`  
`T -> bbQ`  
`T -> bb`  
`Q -> aTQ`  
`Q -> aT`

# Оценка асимптотики оптимизированного парсера
В худшем случае придётся заполнить cS, cP, cT, cQ для всех позиций. В функции iS 3 вложенных цикла + функция count. В других функциях такого нет, поэтому для оценки худшего случая считаем, что вызывали лишь iS. Поскольку all_pos1, all_pos2, all_pos3 содержат максимум n позиций, то учитывая функцию count, и то, что позиций всего 4 * n,  получим, что сложность в худшем случае - O(n^5).
